## Verdict

**INADEQUATE.** 3 Blocker, 8 Major, 5 Minor.

The worked examples of §B2 and the CT-L tests use exact micro-USD values. The four B13 property tests and the P4-S37 property test are seeded, print the seed, and use an oracle (`refSplit`) that shares no code with the provider. That part is strong. But three money guards of the posting templates (`templates.ts`) survive a mutant. Two of them I proved with a run: a supplier gets a credit on a correction that is its own fault, and a buyer gets a refund that is larger than the charge. The ledger checks each line against the same template that settlement uses (C06 §8 check 2). Thus only an exact-value test or an oracle can find a defect in a template. The ledger cannot find it. Also `templates.ts` and `deviation.ts` are not in the Stryker `mutate` list.

## Focus questions of the brief

**(a) CS-9 / D-15: route `route-u` with weights 10⁹ : 1.** This does not hide a commission defect. The usage suite expects M5 entries `B −a`, `S:sup-u:earn +a`. With commission weight 1, the Webster split gives the commission 0 for every amount below 5 × 10⁸ µ, so the template omits the zero entry and the suite entries are the template. If the template drops the commission party for all routes, the C06 suite still passes, but these tests fail: `usage.test.ts` `P4-S74` (`SH:commission 225` and `SH:commission 2`), `C06 CT-L2` (`SH:commission −90`), `P4-S75`, `P4-S85`, `C06 CT-L5 a usage batch sent again three times`, and the four property tests (the `refSplit` oracle includes the commission). If a later suite amount reaches 5 × 10⁸ µ, the suite fails loudly with `invalid`. It does not pass in silence. Conclusion: the real-ledger C06 run proves nothing about the commission, but the unit level covers it at its owning level. No finding.

**(b) C06 PENDING entry.** The entry was replaced by a real provider run, not removed without one. `slices/account/money/test/contract.c06.test.ts` runs `runC06ProviderSuite('real ledger', …)` on the real settlement and ledger, and `test:contracts` shows the `[real ledger]` usage entries green. `contracts/suites/test/contract.c06.test.ts` now has only an export check. Three text defects remain (TR-14).
